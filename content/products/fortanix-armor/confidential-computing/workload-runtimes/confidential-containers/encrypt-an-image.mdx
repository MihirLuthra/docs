The encryption tool encrypts each layer of an image and wraps the layer key with a key-encryption key (KEK) in DSM. Only a TEE that DSM trusts gets the layer key unwrapped.

## Before you begin

- A DSM app with an API key, to encrypt with.
- Docker, signed in to the registry you push the encrypted image to.
- The image to encrypt, pushed to a registry.

## Encrypt the image

1. Create `dsm-config.json`.

   ```json
   {
     "api-endpoint": "<DSM_URL>",
     "api-key": "<DSM_API_KEY>"
   }
   ```

   - `<DSM_URL>` is your DSM endpoint, for example `https://amer.smartkey.io`.
   - `<DSM_API_KEY>` is the API key of the DSM app you encrypt with.

   Keep this file with the people who encrypt images, and out of the image.

2. Encrypt the image.

   ```bash
   docker run -v <PATH>/dsm-config.json:/dsm-config.json:ro \
     -v ~/.docker/config.json:/root/.docker/config.json \
     {{coco-keyprovider.artifact}}:{{coco-keyprovider.version}} /dsm-encrypt.sh \
     --fortanix-dsm-config /dsm-config.json \
     --input-image docker://<IMAGE>:<TAG> \
     --output-image docker://<ENCRYPTED_IMAGE>:<TAG> \
     --kek-name <KEK_NAME> \
     --kek-mode shared
   ```

   - `<PATH>` is the folder with `dsm-config.json`.
   - `<IMAGE>:<TAG>` is the image to encrypt.
   - `<ENCRYPTED_IMAGE>:<TAG>` is where to push the encrypted image.
   - `<KEK_NAME>` is the name of the key-encryption key in DSM.

   Use `--kek-mode per-layer` for a key per layer. Only the encrypted image is pushed.

## Verify

- The encrypted image is in the registry at `<ENCRYPTED_IMAGE>:<TAG>`.
