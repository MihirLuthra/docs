CCM certifies a pod only when its measurements match an approved build. The measurements come from the runtime release installed on the infrastructure, the shape of the confidential VM, and the pod's InitData. The container image is not part of them.

<Callout type="note" title="No supported tool yet">

Fortanix doesn't currently provide a supported way to take measurements for Confidential Containers. The ways on this page work, but you run them yourself. The CNCF Confidential Containers project plans to publish [reference values](https://github.com/confidential-containers/reference-values) for its releases, which will give a supported route in future.

</Callout>

## When to take them again

- A new Confidential Containers release, for example with a kernel patch. It changes the measurements of every pod.
- A change to the pod's InitData.
- On Intel TDX, a change to the shape of the host or the pod, such as the number or model of GPUs, the CPU generation, or the memory.

## Write the InitData

The InitData holds the pod's attestation and key broker settings, and its hash is part of the measurements. The workload must run with exactly the value you measure with.

1. Create `initdata.toml`.

   ```toml
   version = "0.1.0"
   algorithm = "sha384"
   [data]
   "aa.toml" = '''
   [token_configs.ccm_as]
   ccm_domain_names = ["<CERT_DOMAIN>"]
   '''
   "cdh.toml" = '''
   [kbc]
   name = "ccm_kbc"
   url = "<DSM_URL>"
   [kbc_configs.ccm_kbc]
   dsm_app_id = "<DSM_APP_UUID>"
   '''
   ```

   - `<CERT_DOMAIN>` is the certificate domain of the application in CCM.
   - `<DSM_URL>` is your DSM endpoint.
   - `<DSM_APP_UUID>` is the DSM app the workload authenticates as.

2. Encode it.

   ```bash
   initdata=$(cat initdata.toml | gzip | base64 -w0)
   ```

## Take the measurements

<Tabs groupId="tee">
<Tab label="Intel TDX">

On Intel TDX, the measurements include the ACPI tables of the confidential VM, and those depend on its shape. Measure on a host that is nearly the same as the one the model will run on, with the same GPU count and models and the same CPU generation, and with the same runtime release.

1. Start a measurement pod with the runtime class the workload uses, the annotation `io.katacontainers.config.hypervisor.cc_init_data` set to `$initdata`, and the same resources as the workload.
2. In the pod, fetch the TDX evidence from `http://127.0.0.1:8006/aa/evidence`, and read the measurements from the quote.

   | Value | Byte offset in the quote |
   |---|---|
   | MRTD | 184 |
   | MRCONFIGID | 232 |
   | RTMR0 | 376 |
   | RTMR1 | 424 |
   | RTMR2 | 472 |
   | RTMR3 | 520 |
