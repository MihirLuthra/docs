A shared workflow lets one CCM account run an application that another account owns, without the owner handing over the application. The **publisher** owns the application, and the **consumer** runs it on its own infrastructure. The two link their groups as collaborating groups, and both approve the workflow.

Collaborating groups link two accounts. Within one account, use a normal workflow.

## Before you begin

- Each side has its own CCM account and a group.
- The publisher has [registered the application](../applications/register-an-application.mdx) and its builds are approved.

## Link the groups

| Step | Publisher | Consumer |
|---|---|---|
| 1 | Open the group and click **COLLABORATE**, then **+ GENERATE**, then **COPY**. Send the token to the consumer. | |
| 2 | | Open the group, click **ACCEPT TOKEN**, paste the token and click **PROCEED**. |
| 3 | Go to **COLLABORATION GROUPS**, open the **PUBLISHER** tab, and in the row's menu click **ACCEPT**. | |

Under **Groups** > **COLLABORATION GROUPS** > **CONSUMER**, the consumer sees the link as **Pending** until the publisher accepts, then **Accepted**.

## Create and approve the workflow

| Step | Publisher | Consumer |
|---|---|---|
| 1 | | Go to **Workflows** and click **+ ADD WORKFLOW**. Enter a **Name**, select the group, and click **SAVE**. |
| 2 | | Add an application placeholder, assign it to the publisher's group, and click **SAVE AS DRAFT**. |
| 3 | Go to **Workflows** > **Draft**, select the workflow, click the placeholder, select the application image, and click **SAVE DRAFT**. | |
| 4 | | Open the draft, click **SAVE AND REQUEST APPROVAL**, and confirm with **REQUEST APPROVAL**. |
| 5 | Go to **Workflows** > **Pending**, select the workflow, click **VIEW REQUEST**, then **APPROVE**. | |
| 6 | | Approve the workflow. It moves to **Approved**. |

The publisher approves first, and the consumer can't approve until it has. Each side can change only its own part of the workflow.

## Change or end the collaboration

- An approved workflow can't be edited. **EDIT WORKFLOW** creates a new version, which replaces the old one once both sides approve it.
- Either side can end the collaboration from **COLLABORATION GROUPS** with **REVOKE**. The workflow then stops.

## Verify

- The workflow is listed under **Workflows** > **Approved**.
