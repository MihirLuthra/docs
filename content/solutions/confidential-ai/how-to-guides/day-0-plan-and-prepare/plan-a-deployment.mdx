Settle these before day 1: who plays which role, which runtime runs the model, and what the parties send each other.

## Choose the deployment

Each deployment has an end-to-end guide that orders every task in this section.

| Deployment | Model owner | Infrastructure provider | Model consumer |
|---|---|---|---|
| [Vendor to customer](../end-to-end/vendor-to-customer.mdx) | Model vendor | Customer | Customer |
| [Vendor, NCP, enterprise](../end-to-end/vendor-ncp-enterprise.mdx) | Model vendor | NCP | Enterprise |
| [In-house, own infrastructure](../end-to-end/in-house-own-infrastructure.mdx) | Enterprise | Enterprise | Enterprise |
| [In-house, cloud or NCP](../end-to-end/in-house-cloud-or-ncp.mdx) | Enterprise or model vendor | Cloud or NCP | Enterprise or model vendor |
| [Open model on an NCP](../end-to-end/open-model-on-ncp.mdx) | Open-source project (public weights) | NCP | Enterprise |
| [Open model on own GPUs](../end-to-end/open-model-on-own-gpus.mdx) | Open-source project (public weights) | Enterprise | Enterprise |

With an open model, nobody holds the owner's tasks: the weights are public, and the consumer builds and registers the workload itself.

## Choose the runtime

Both run the model in an Intel TDX TEE with NVIDIA GPUs, attested by CCM. They differ in how the model is packaged and run.

| | [Confidential Containers](/products/fortanix-armor/confidential-computing/workload-runtimes/confidential-containers/overview) | [Enclave OS](/products/fortanix-armor/confidential-computing/workload-runtimes/enclave-os/overview) |
|---|---|---|
| Runs on | Kubernetes | Docker on the host |
| One TEE per | Pod | Converted container |
| Model protection | The whole image is encrypted; DSM unwraps its key | The model files are encrypted with a PGP key in DSM, and decrypted when the workload starts |
| Measurements come from | The runtime install and the pod's InitData | The converted image |
| Guest firmware and kernel | From the runtime install, the same for every pod | In each converted image |

Every guide in this section has a tab for each runtime. Pick one, and the tabs follow it.

## Decide the accounts

- The model owner and the model consumer each have their own CCM account. A [shared workflow](/products/fortanix-armor/confidential-computing/ccm/workflows/shared-workflows) links them. When one organization is both, there is one account and no shared workflow.
- The GPU nodes are enrolled in the model consumer's CCM account.
- The model owner has a DSM account, which holds the model's key.

## List what the parties exchange

| What | From | To | Used for |
|---|---|---|---|
| Join token | Model consumer | Infrastructure provider | Enrolling the nodes in the consumer's CCM account |
| Zone CA certificate | Model consumer | Model owner | Letting the owner's DSM app trust the workload's certificate |
| Collaboration token | Model owner | Model consumer | Linking their CCM groups for the shared workflow |

Send them over a channel you trust. Anyone with the join token can enrol a node in the consumer's account.
