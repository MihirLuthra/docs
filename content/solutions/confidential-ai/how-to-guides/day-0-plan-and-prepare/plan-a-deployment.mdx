## Choose the runtime

The model runs in a TEE with all three. They differ in what you build, where it runs, and how the model is protected.

| Compared | Confidential Containers | Fortanix Enclave OS | Custom confidential VM |
|---|---|---|---|
| What it is | Kubernetes pods in TEEs, based on the CNCF [Confidential Containers](https://confidentialcontainers.org/) project | A converter that turns a container image into an Enclave OS container. The converted container is what runs. | A confidential VM you build yourself |
| What you build | A normal container image | A normal container image, which you then convert | The whole VM image, with its firmware, kernel and disk |
| Where it runs | Kubernetes, with the Confidential Containers runtime installed on the hosts | Anywhere that runs containers, such as Docker or Kubernetes | Wherever you start it, for example with QEMU |
| The TEE | One TEE per pod | The container starts its own TEE from within | One TEE per VM |
| How the model is protected | The image layers are encrypted with ocicrypt, and DSM wraps the layer keys. Inside the TEE, the layers are decrypted as the image is pulled, after attestation and before the container starts. | The model files are encrypted separately, with a key stored in DSM. The workload decrypts them when it starts, after attestation. | Your choice |
| Supported TEEs | <SupportedTees runtime="confidential-containers" /> | <SupportedTees runtime="enclave-os" /> | Your choice |

The supported TEEs come from the [support matrix](../../support-matrix.mdx), which lists the tested versions for each.
