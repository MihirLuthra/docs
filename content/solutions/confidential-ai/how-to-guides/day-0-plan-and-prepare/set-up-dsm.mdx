The model owner does this. The key that protects the model stays in DSM, and DSM releases it only to a workload with a certificate from the consumer's CCM account.

You need two DSM apps in one group. One encrypts the model, and the workload authenticates as the other.

## Before you begin

- A Fortanix DSM account.
- For the second app, the model consumer's zone CA certificate, from [Set up CCM](prepare-the-infrastructure.mdx#set-up-ccm). You can create the first app before it arrives.
- The certificate domain the workload will have in CCM, for example `chat.northwind.example`.

## Create the apps

1. In DSM, create a group for the model, such as `llama-chat-keys`, or use an existing one.
2. Create the app you encrypt with. In the group, go to **APPS** and click **ADD APP**, with **Interface** set to REST API and **Authentication Method** set to API Key.
3. Click **SAVE**, and copy its API key. Keep it with the people who encrypt models, and out of every image. You can now [protect the model](protect-the-model.mdx).
4. Once the consumer sends its zone CA certificate, create the app the workload authenticates as. Click **ADD APP** again, then set these fields.

   | Field | Value |
   |---|---|
   | **Interface** | REST API |
   | **Authentication Method** | Trusted CA |
   | **DNS Name** | The certificate domain of the workload |
   | **Upload Trusted CA Cert** | The consumer's zone CA certificate |

5. Click **SAVE**, and note the app's UUID.
