Skip this when one organization both owns and runs the model. Otherwise the consumer runs the owner's application from its own CCM account, through a shared workflow. The model owner is the **publisher**, and the model consumer the **consumer**.

A workflow sets which build of the application runs, with which application configuration. The configuration lives in CCM, not on the host, so a host administrator can't change it unseen. The workload fetches it from CCM when it starts, using its application configuration ID, which also tells CCM which workflow the workload runs in. In a shared workflow, the owner picks the application, build and configuration, and both sides approve. See [CCM concepts](/products/fortanix-armor/confidential-computing/ccm/concepts) for more.

The shared workflow also protects the key. The consumer's CCM account can issue a certificate with the owner's application name, `<APPLICATION_ID>.app.fortanix.cloud`, only for the application in a workflow the owner approved. That is the name DSM's Trusted CA app expects ([Set up DSM](../day-0-plan-and-prepare/set-up-dsm.mdx#create-the-trusted-ca-app)).

## Before you begin

- The model owner has [protected the model](../day-0-plan-and-prepare/protect-the-model.mdx): its build is approved, and it has an application configuration for the build.
- The consumer has a group in its CCM account, from [Set up CCM](../day-0-plan-and-prepare/set-up-ccm.mdx#model-consumer).

## Find the application configuration ID

The consumer runs the workload with it.

1. Go to **Workflows** > **Approved** and click **VIEW DETAILS** on the workflow.
2. Click the information icon on the application's node, and copy the **Application configuration ID**.

## Verify

- The workflow is under **Workflows** > **Approved**, in both accounts.
