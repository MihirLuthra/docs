Anything that changes a workload's measurements needs a new approved build before the workload restarts. Otherwise CCM refuses its certificate, and DSM releases no key.

| Change | Measurements change? | What to do first |
|---|---|---|
| New model or application image | Yes, with Enclave OS (a new converted image). With Confidential Containers, only if the InitData changes. | Add and approve a build |
| Confidential Containers runtime upgrade | Yes, for every pod on the upgraded nodes | Add and approve a build for every workload |
| New Enclave OS converter | Converted again, so yes | Add and approve a build |

## Update the model

1. The model owner encrypts the new model and builds the new image, as in [Protect the model](../day-0-plan-and-prepare/protect-the-model.mdx).
2. If the measurements changed, the owner [adds a build](/products/fortanix-armor/confidential-computing/ccm/applications/register-an-application#add-a-build) with a new **Build Version**, and [approves it](/products/fortanix-armor/confidential-computing/ccm/applications/approve-builds-and-domains).
3. With a shared workflow, an approved workflow can't be edited: **EDIT WORKFLOW** creates a new version, which replaces the old one once both sides approve it.
4. The consumer [deploys](../day-1-deploy/deploy-and-verify.mdx) the new image.

The old build stays approved, so workloads of the old version still get certificates.

## Upgrade the runtime

<Tabs groupId="runtime">
<Tab label="Confidential Containers">

Every pod boots the guest firmware, kernel and root filesystem of the runtime install, so an upgrade changes the measurements of every workload on the node.

1. Take the new runtime version from the [support matrix](../../support-matrix.mdx).
2. On a node with the new version, [measure each workload](/products/fortanix-armor/confidential-computing/workload-runtimes/confidential-containers/measure-a-workload) with its unchanged InitData.
3. Add and approve a build for each, in the model owner's CCM account.
4. Upgrade the remaining nodes, then restart the workloads on them.

## Update the hosts

- After a BIOS or microcode update, check `/var/log/mpa_registration.log` on the host: it shows `Registration Flow - TCB_RECOVERY passed successfully`.
- Before changing GPU firmware, VBIOS or driver, check the combination in the [NVIDIA Secure AI compatibility matrix](https://www.nvidia.com/en-us/data-center/solutions/confidential-computing/secure-ai-compatibility-matrix/).

## Verify

- The new build is **Deployed** on the application's **Builds** tab, and the audit log shows a successful `REQUEST_APP_CERTIFICATE` after the restart.
